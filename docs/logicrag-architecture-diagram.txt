# LogicRAG Pipeline Architecture

## Complete Flow

```
INPUT: Question
  |
  v
┌─────────────────────────────────────────────────────────┐
│ STAGE 1: WARM-UP RETRIEVAL                              │
├─────────────────────────────────────────────────────────┤
│ 1. Retrieve top-k documents for original question       │
│ 2. Create initial summary from contexts                 │
│ 3. Run WARM-UP ANALYSIS prompt                          │
│    └─→ Output: {can_answer, dependencies, ...}          │
└─────────────────────────────────────────────────────────┘
  |
  v
┌──────────────────────────────┐
│ Can answer with warmup data? │
└──────────────────────────────┘
  |
  ├─ YES ─→ [GENERATE FINAL ANSWER] ──→ OUTPUT: Answer
  |
  └─ NO ──→ Proceed to Stage 2
             |
             v
┌─────────────────────────────────────────────────────────┐
│ STAGE 2: DEPENDENCY ANALYSIS                            │
├─────────────────────────────────────────────────────────┤
│ 1. Extract dependencies from warmup analysis            │
│    Dependencies = ["Q1", "Q2", "Q3"]                     │
│                                                          │
│ 2. Run DEPENDENCY PAIRS prompt                          │
│    Input: question + dependencies                        │
│    Output: [[1,0], [2,1]] (pairs of indices)            │
│                                                          │
│ 3. Build Dependency DAG                                 │
│    0: Q1 ────────────────┐                              │
│         \                 v                              │
│          └→ 1: Q2 ───→ 2: Q3                            │
│                                                          │
│ 4. Topological Sort                                     │
│    DFS traversal → [0, 1, 2] (sorted order)             │
└─────────────────────────────────────────────────────────┘
  |
  v
┌─────────────────────────────────────────────────────────┐
│ STAGE 3: AGENTIC ITERATIVE RETRIEVAL                    │
├─────────────────────────────────────────────────────────┤
│ For each dependency in topological order (max_rounds):  │
│                                                          │
│ ┌─────────────────────────────────────────────────┐     │
│ │ Round 1: Process dependency Q1                   │     │
│ ├─────────────────────────────────────────────────┤     │
│ │ 1. Retrieve top-k for Q1                         │     │
│ │ 2. Refine summary: REFINE SUMMARY prompt         │     │
│ │    Current + New → Integrated summary            │     │
│ │ 3. Check satisfiability:                         │     │
│ │    DEPENDENCY-AWARE RAG prompt                   │     │
│ │    → can_answer? {true/false}                    │     │
│ │ 4. If can_answer=true → Skip to FINAL ANSWER     │     │
│ │    Else → Continue to next dependency            │     │
│ └─────────────────────────────────────────────────┘     │
│                  |                                       │
│                  v                                       │
│ ┌─────────────────────────────────────────────────┐     │
│ │ Round 2: Process dependency Q2                   │     │
│ ├─────────────────────────────────────────────────┤     │
│ │ 1. Retrieve top-k for Q2                         │     │
│ │ 2. Refine summary (rolling, not accumulating)    │     │
│ │ 3. Check DEPENDENCY-AWARE RAG                    │     │
│ │ 4. If can_answer=true → Skip to FINAL ANSWER     │     │
│ │    Else → Continue                               │     │
│ └─────────────────────────────────────────────────┘     │
│                  |                                       │
│                  v                                       │
│ ┌─────────────────────────────────────────────────┐     │
│ │ Round 3: Process dependency Q3                   │     │
│ ├─────────────────────────────────────────────────┤     │
│ │ 1. Retrieve, refine, check                       │     │
│ │ 2. If max_rounds reached → Exit loop             │     │
│ └─────────────────────────────────────────────────┘     │
│                                                          │
│ KEY: Rolling memory (not accumulation)                  │
│      Summary refined each round → token efficiency      │
└─────────────────────────────────────────────────────────┘
  |
  v
┌─────────────────────────────────────────────────────────┐
│ STAGE 4: FINAL ANSWER GENERATION                        │
├─────────────────────────────────────────────────────────┤
│ 1. Input: question + accumulated summary                │
│ 2. Run FINAL ANSWER prompt                              │
│    "Give ONLY direct answer, no explanation"            │
│ 3. Output: Concise answer string                        │
└─────────────────────────────────────────────────────────┘
  |
  v
OUTPUT: (answer, contexts_used, num_rounds)
```

## Summary Refinement Process (Key Efficiency)

```
ACCUMULATION APPROACH (Traditional, Token-Heavy):
Round 1: Retrieve [C1, C2, C3]  →  Facts = [C1, C2, C3]
Round 2: Retrieve [C4, C5]      →  Facts = [C1, C2, C3, C4, C5]
Round 3: Retrieve [C6, C7]      →  Facts = [C1...C7]
Problem: Token count grows with each round → 2000→3000→4000 tokens

LOGICRAG APPROACH (Rolling Summary, Token-Efficient):
Round 1: Summary = "From [C1,C2,C3], learned: X, Y, Z" (200 tokens)
Round 2: Retrieve [C4,C5]
         Prompt: "Refine summary [200 tokens] with [C4,C5]"
         Summary = "X, Y, Z, and also: A, B" (220 tokens) ← Deduplicated!
Round 3: Retrieve [C6,C7]
         Prompt: "Refine summary [220 tokens] with [C6,C7]"
         Summary = "X, Y, Z, A, B, and: D" (240 tokens) ← Still ~200!
Benefit: Constant summary size, not linear growth
         30-40% token reduction vs. accumulation
```

```
                           |

                           |

                     DEPENDENCY-AWARE check

                    _______|_______
                   |               |
                 YES             NO
                  |               |
                  v               v

```

## Prompt Call Sequence (Per Dependencies)

```
Question: "Who directed Inception and where was it filmed?"

1. WARM-UP ANALYSIS
   Q: "Who directed Inception and where was it filmed?"
   Context: [initial retrieval results]
   → {can_answer: false, dependencies: ["director", "filming location"]}

2. DEPENDENCY PAIRS
   Q: "Who directed Inception and where was it filmed?"
   Deps: ["director", "filming location"]
   → {dependency_pairs: []}  (no dependencies between these)
   → Topological: ["director", "filming location"]

3. Round 1: INITIAL SUMMARY + DEPENDENCY-AWARE
   Q: "Who directed Inception and where was it filmed?"
   Dep: "director"
   Summary: "Christopher Nolan directed Inception"
   → {can_answer: false} (missing filming location)

4. Round 2: REFINE SUMMARY + DEPENDENCY-AWARE
   Q: "Who directed Inception and where was it filmed?"
   Dep: "filming location"
   Old Summary: "Christopher Nolan directed Inception"
   New Contexts: [filming location info]
   → Refined: "Christopher Nolan directed Inception. Filmed in UK/USA."
   → {can_answer: true} ← EARLY STOP

5. FINAL ANSWER
   Q: "Who directed Inception and where was it filmed?"
   Summary: "Christopher Nolan directed Inception. Filmed in UK/USA."
   → "Christopher Nolan; filmed in various UK and USA locations"

RESULT: 2 rounds, 2 retrieval calls, ~400 tokens total
```

## Configuration Impact

```
Config: max_rounds = 3
├─ Limits iterative retrieval to 3 rounds max
├─ Typical scenario: exits after 1-2 rounds (early stopping)
└─ Safety valve if decomposition produces many dependencies

Config: top_k = 5
├─ Retrieve top 5 documents per dependency
├─ Higher k → more context, more tokens
└─ Lower k → faster, less coverage

Config: filter_repeats = True
├─ Skip chunks already retrieved in previous rounds
├─ Useful for small corpora
└─ Minimal impact on large corpora

Config: temperature = 0
├─ Deterministic LLM responses
├─ Consistent dependency ordering
└─ Reproducible results
```

## Error Handling & Fallbacks

```
JSON Parse Failure
  └─ fix_json_response() removes:
     - Markdown code blocks (```json...```)
     - Trailing commas
     - Extra whitespace
  └─ If still invalid: return empty dict or defaults

Can't Extract Dependencies
  └─ Fallback: treat question as single dependency
  └─ Run single retrieval round

Can't Determine Order
  └─ Fallback: use extraction order (not topologically sorted)
  └─ May be suboptimal but still works

Max Rounds Exceeded
  └─ Generate answer from current summary
  └─ No error raised, graceful degradation
```

## Token Budget Estimation

```
Per Question (average):
├─ Warm-up prompt: ~800 tokens (Q + context + JSON output)
├─ Dependency pairs: ~400 tokens
├─ Per round (2 avg):
│  ├─ Refine summary: ~300 tokens
│  ├─ Dependency-aware: ~400 tokens
│  └─ Subtotal per round: 700 tokens
├─ Final answer: ~300 tokens
│
└─ TOTAL: ~800 + 400 + (2×700) + 300 = ~2700 tokens

vs. Baseline (accumulation):
  Warm-up: 800
  Per round (3x): ~1000 each (contexts accumulate)
  Final: 300
  TOTAL: ~4100 tokens (48% more!)

Savings: 2700 vs 4100 = 34% reduction
```
